# 性能验证记录

测试素材为仓库自带图片，使用开发云环境 Python 3.12。以下时间不包含进程导入、应用解包启动、图片上传和浏览器绘制；不代表用户设备上的耗时保证。

## 首次识别（未命中图片结果缓存）

每次使用新的 Python 进程，对比旧字形匹配实现和批量取样实现。50×50 图片各测三轮；下表为 OCR、求解和提示生成之和。

| 图片 | 棋盘 | 优化前 | 优化后 |
| --- | --- | --- | --- |
| debug.png | 50×50 | 4.516～4.575 秒 | 2.448～2.533 秒 |
| image.png | 30×25 | 0.744 秒 | 0.407 秒 |
| image copy.png | 30×25 | 0.718 秒 | 0.398 秒 |

50×50 平均耗时由 4.544 秒降到 2.488 秒，约减少 45%。三张图的新旧完整结果 JSON（OCR 数字、当前棋盘、解答、冲突和提示）逐项相等。

优化将字形匹配中的整图平移替换为一次批量取样，保留原有循环边界语义和双向距离评分；100 组随机字形的评分与原算法严格相等。没有缩减模板、降低识别精度或跳过冲突检查。

## 相同图片缓存

浏览器真实上传 debug.png 两次，第二次服务端命中耗时约 0.003 秒。单独启动另一 Python 进程读取相同磁盘缓存，同样无需调用 OCR 或求解；测试在缓存未命中时会直接失败，从而确认跨进程复用。

缓存按版本与原始图片字节计算 SHA-256；改名可命中，重新编码或修改图片不会误用旧结果。并发相同请求只计算一次（同进程内），最多保留 32 份结果；错误不会缓存，缓存不可写时回退到正常识别。

## 界面验证

真实上传流程已验证；1440、1024、768、390 像素窗口宽度下，加粗线索无裁切、页面无横向溢出。无冲突、无解、100% 完成三类提示分别检查。无冲突仅表示当前识别结果未发现矛盾，不代替人工核对 OCR。
